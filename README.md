# Bayer

Персональное приложение байера: Next.js 16, React 19, TypeScript, Supabase Auth/PostgreSQL/Storage. Мобильный клиент без регистрации: крупные фото, `− / количество / +`, нижняя кнопка «Готово», проверка заказа в модальном окне.

## Сценарий

1. Войти по email/паролю, открыть «Создать», загрузить фото (JPG/PNG/WebP/HEIC/HEIF), указать закупку, вес, работу и поставщика. Фотографии обрабатываются последовательно до 2000 px, отдельно создаются миниатюры 480 px.
2. Выбрать карго для всего заказа: Авто 30 смн/кг или Авиа 60 смн/кг. По умолчанию Авто. Цена = CNY × 1,4 + граммы / 1000 × тариф + работа. Примеры: 40 ¥, 80 г, работа 10 → 68,40 / 70,80 смн. Неуказанная закупка не становится нулём.
3. Черновик автоматически сохраняется на сервере; IndexedDB хранит локальную копию и ещё не сохранённые фото. При сетевой ошибке можно повторить сохранение. Стабильные UUID и версия защищают от дублей и перезаписи другой вкладкой. Добавление/удаление, перестановка и общие параметры доступны и у существующего черновика.
4. Опубликовать сохранённый состав, поделиться ссылкой. До подтверждения ссылку можно отозвать или заменить.
5. Клиент выбирает количество, может ввести его с клавиатуры и увеличить фото. В окне проверки доступны общая заметка до 1000 символов и раскрываемые заметки позиций до 300. Выбор и заметки сохраняются локально до успеха.
6. Подтверждение атомарно создаёт снимок версии. Повтор того же запроса возвращает тот же результат. При повторном открытии действующей ссылки видна квитанция без закупочных цен и внутренних данных.
7. В «Закупке» — только выбранные позиции, поставщики и заметки. Записывайте частично купленное/отменённое количество, фактическую цену CNY, реальный курс, фактическое карго всей позиции, дополнительные расходы и проблемы. «Заказано» доступно только после обработки всех позиций.
8. Для исправлений открыть повторное согласование: прежнее подтверждение сохраняется, выбранные количества восстанавливаются, закупки не копируются. Уменьшить новый выбор ниже уже закупленного/отменённого количества нельзя.
9. Отдельно записывать оплату, возврат или дополнительный расход. Плановая прибыль отделена от фактической. Неизвестные затраты показываются как неизвестные; аванс не выдаётся за окончательную прибыль.
10. Все статусы удаляются по сроку `created_at + 25 суток UTC`. Срок неизменяемый. В кабинете есть обратный отсчёт и предупреждения. Cron удаляет строки и фотографии, оставляя только обезличенные финансовые суммы по месяцам.

Каталога нет. Каждый заказ владеет своим набором товаров. Старые пути фотографий сохраняются; удаление общего файла возможно только после исчезновения всех ссылок на него из других заказов и снимков.

## Локальный запуск

Node.js 22.18+:

```sh
npm ci
npm run dev
```

Публичные настройки в `.env.local`:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_KEY
```

Создайте аккаунт байера через Supabase Auth и отключите публичную регистрацию. Базовая конфигурация совместима с существующим подключением Bayer. Новые инсталляции применяют миграции по имени; работающая база выпускается по [инструкции безопасного релиза](docs/RELEASE.md), после внешней резервной копии и проверки на staging.

## Защита и обслуживание

RLS ограничивает административные данные владельцем. Anonymous не читает таблицы и не вызывает RPC подтверждения. Edge Function проверяет случайный UUID ссылки, срок, отзыв, revision и payload, ограничивает запросы через PostgreSQL. Публичный ответ формируется из allowlist полей, заметки выводятся только как React text. Закупка, прибыль, owner ID и поставщики не попадают в публичный API.

Для фонового обслуживания в Vercel задаются только серверные `SUPABASE_SERVICE_ROLE_KEY` и `CRON_SECRET`. `vercel.json` регистрирует ежедневный `/api/maintenance` в 01:15 UTC. Задача требует Bearer secret, использует lease, ограниченные пакеты и backoff очереди Storage. После истечения срока API закрывается сразу; физическая очистка происходит при запуске cron (обычно в течение суток). Незавершённые загрузки без ссылок удаляются после 24 часов. Мониторьте успешные запуски `buyer_job_runs`; журнал хранится 30 дней и содержит только счётчики.

Telegram остаётся опциональным. Настройки: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_BUYER_ID`, `BAYER_ADMIN_URL` — в Edge Function Secrets, а для фоновых повторов также в серверной среде Vercel. Уведомление содержит номер, количество и ссылку на кабинет. Ошибка Telegram не отменяет заказ. Возможны повторные сообщения при потерянном ответе Telegram.

## Проверки

```sh
npm run check
npm run build
npx playwright install --with-deps chromium webkit
npm run test:e2e
```

Unit/API и PostgreSQL-тесты проверяют цены, RLS, атомарность/повторы, версии, заметки, частичные закупки, деньги, cron, границу срока и общие фотографии. PostgreSQL работает через PGlite; браузерные сценарии обращаются к настоящим SQL/RPC через loopback HTTP-адаптер, Auth и Storage transport тестовые. В E2E есть Chromium desktop/iPhone и WebKit iPhone, HEIC, сетевой сбой/восстановление, 300 товаров, тёмная тема и отсутствие горизонтальной прокрутки.

Состояние фактически выполненных проверок и ограничения фиксируются в отчёте, а не подразумеваются наличием тестовых файлов. Реальные Supabase Storage/Edge gateway, физический iPhone и доставка Telegram проверяются отдельно на staging.
