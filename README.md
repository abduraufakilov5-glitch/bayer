# Bayer — MVP для байера

Next.js 16 + TypeScript + Tailwind CSS 4 + Supabase Auth, PostgreSQL и приватный Storage.

## Основной сценарий

1. Байер входит по email и паролю.
2. Создаёт заказ: название, фотографии JPG/PNG/WebP, названия товаров, закупочную цену в юанях, вес, стоимость работы и ссылку поставщика.
3. В черновике редактирует названия, цены и ссылки или удаляет товары. Сохранён исходный расчёт: закупка в CNY × 1,4 + 30 смн/кг + работа байера. Вес по умолчанию — 80 г.
4. Нажимает «Создать» в блоке ссылки и отправляет ссылку клиенту.
5. Клиент без регистрации выбирает количество (0–99), нажимает «Готово», проверяет состав и подтверждает.
6. Кабинет показывает номер, выбранные товары, количество, общее количество и время подтверждения. Открытый кабинет обновляется каждые 15 секунд и при возвращении во вкладку.
7. Байер нажимает «Заказано», затем «Завершено».

Название можно изменить на любом этапе. Удаление переносит заказ в «Корзину», отключает клиентскую ссылку и исключает заказ из финансовой сводки; заказ можно восстановить.

Статусы базы: `draft → waiting → received → ordered → completed`. В интерфейсе они переведены на русский. После публикации состав фиксируется. Пустой заказ нельзя опубликовать. Товары без цены можно выбирать; отсутствие цены не превращается в нулевую цену. Итоговая сумма показывается только когда цены известны для всех выбранных товаров.

До 30 фото за одну загрузку, 8 МБ на фото, 300 товаров в заказе.

## Дизайн, удобство и скорость

- Светлая и тёмная темы с системным шрифтом, мобильной навигацией и крупными областями нажатия; тема запоминается, внешние шрифты и библиотеки анимации не загружаются.
- На главной есть финансовая сводка: выручка, закупка с доставкой и заработок байера за всё время и текущий месяц. Значения фиксируются при подтверждении заказа, поэтому история не меняется после правок каталога.
- Общие параметры веса и работы: применяются к новым фото, кнопка «Применить ко всем» меняет текущие товары и позволяет отменить действие. Курс и тариф доставки не меняются.
- «Поделиться» открывает системное меню телефона; если оно недоступно, копирует ссылку. Отмена системного меню не считается ошибкой.
- Поиск по названию/номеру с задержкой 250 мс, серверные фильтры и страницы по 24 заказа. Устаревшие запросы отменяются.
- Подписи фотографий получаются пакетно и сохраняются на странице на 50 минут. У опубликованного заказа неизменяемый состав не загружается повторно каждые 15 секунд.
- Если у старого товара нет исходной закупочной цены, редактирование названия не пересчитывает его существующую конечную цену. Для пересчёта укажите закупку.
 Старый каталог сохранён для совместимости существующих данных, но убран из основного интерфейса MVP. Существующие цены не пересчитываются.

## Запуск

Требуется Node.js 22.18+.

```sh
npm ci
npm run dev
```

Проект использует существующее подключение Bayer. Для другого Supabase задайте в `.env.local` (до сборки):

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Создайте аккаунт байера в Supabase Auth; для закрытого кабинета отключите публичную регистрацию. Секретный service-role ключ в Next.js не нужен.

Для новой базы примените все файлы `supabase/migrations/*.sql` по имени. Для существующей установки от 20 сентября последовательно примените `20260922160200_simple_order_mvp.sql` и `20260923004310_order_management_finances.sql`.

```sh
npx supabase functions deploy buyer-public-order --project-ref YOUR_PROJECT_REF --use-api
npm run build
npm start
```

Функция имеет `verify_jwt = false`, поскольку клиент не входит в аккаунт. Её собственная авторизация — случайный UUID-токен ссылки. Одна ссылка соответствует одному заказу. Не используйте ID заказа вместо токена.

## Защита

- RLS ограничивает байера его собственными заказами, товарами, подтверждениями и фотографиями.
- У роли `anon` нет прямого доступа к таблицам или RPC подтверждения. Публичный клиент обращается к Edge Function, которая проверяет токен и возвращает только товары соответствующего заказа. Service-role остаётся в среде Supabase.
- Клиент не получает ссылку поставщика, owner ID, закупочные поля или токены других заказов.
- Фото в приватном Storage выдаются по временным подписанным URL на час. При долгом просмотре перезагрузите страницу; количества восстановятся из локального хранилища.
- Подтверждение атомарно, блокирует строку заказа и проверяет принадлежность всех товаров. Повтор того же запроса возвращает прежний результат.
- Публичные страницы не индексируются, не передают Referer, ответы API не кешируются.

## Telegram (опционально)

В Supabase → Edge Functions → Secrets установите:

- `TELEGRAM_BOT_TOKEN`: токен вашего бота;
- `TELEGRAM_CHAT_ID`: ваш чат с ботом (сначала отправьте боту `/start`);
- `TELEGRAM_BUYER_ID`: UUID вашего аккаунта из Supabase Auth.

Не помещайте эти значения в `NEXT_PUBLIC_*` или Git. Уведомления отправляются только для указанного байера. Если настройки отсутствуют, интеграция отключена. Уведомление содержит номер, общее количество и время подтверждения.

Отправка best-effort: ошибка Telegram не мешает подтверждению. Атомарная блокировка предотвращает обычные параллельные дубли; повтор клиентского запроса может повторить неудачное уведомление. Автоматической фоновой очереди повторов нет. Если Telegram принял сообщение, но ответ потерялся, возможен повтор — строгую exactly-once доставку Telegram Bot API не предоставляет.

## Проверки

```sh
npm run check
npm run build
npm run test:e2e
```

14 unit/API/PostgreSQL тестов: необязательная цена, RLS между байерами, чужие товары, атомарность и повтор подтверждения, приватные поля и обработка ошибок Telegram. 12 браузерных сценариев в Chromium desktop/mobile: авторизация, статусы, фото и отмена неудачного сохранения, выбор, восстановление корзины, подтверждение, товар без цены, неверный токен. Браузерные сценарии используют HTTP-макет Supabase, PostgreSQL тесты — PGlite. В действующем Supabase дополнительно проверен цикл без цены в транзакции с rollback.

Реальная отправка Telegram требует секретов и отдельно не проверена. Safari на физическом iPhone и внешняя публикация обновлённого Next.js не проверялись.
